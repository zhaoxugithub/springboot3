## 📊 核心区别总结

| 对比项 | 顺序消息 | 非顺序消息 |
|--------|----------|------------|
| **发送方法** | `syncSendOrderly(topic, msg, hashKey)` | `syncSend(topic, msg)` |
| **队列选择** | 根据hashKey路由到固定队列 | 随机分配到不同队列 |
| **消费模式** | `ConsumeMode.ORDERLY` | `ConsumeMode.CONCURRENTLY` |
| **消费顺序** | ✅ 严格保证 | ❌ 不保证 |
| **并发度** | 低（同队列串行） | 高（多线程并发） |
| **适用场景** | 订单流程、状态流转 | 通知推送、日志收集 |

## 🔍 深入理解

### 顺序消息的关键

```java
// 使用 orderId 作为 hashKey
rocketMQTemplate.syncSendOrderly("order-topic", message, String.valueOf(orderId));
                                                           ↑
                                                      关键参数！
```

**原理：** RocketMQ 会对 hashKey 进行哈希运算，将结果对队列数取模，确定消息发送到哪个队列。

```
queueId = hash(hashKey) % queueCount
```

因此，相同的 hashKey（如相同的 orderId）会得到相同的 queueId，从而保证消息的顺序性。

### 非顺序消息的特点

```java
// 不指定 hashKey
rocketMQTemplate.syncSend("non-order-topic", message);
```

**原理：** 消息会按照轮询或随机的方式分配到不同队列，多个线程并发消费，无法保证顺序。

## ⚠️ 注意事项

### 顺序消息

1. **消费失败会阻塞** - 如果某条消息消费失败，会阻塞该队列的后续消息
2. **性能较低** - 同一队列内串行消费，吞吐量受限
3. **适度使用** - 只在确实需要保证顺序时使用

### 非顺序消息

1. **需要保证幂等性** - 消息可能重复消费
2. **不能依赖顺序** - 业务逻辑不能依赖消息的消费顺序
3. **性能较高** - 适合高吞吐量场景
